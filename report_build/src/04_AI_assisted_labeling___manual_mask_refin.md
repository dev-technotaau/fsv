# AREA: AI-assisted labeling + manual mask refinement (Step 4)

## SUMMARY
This subsystem auto-labels the scraped fence dataset with a Grounded-SAM 2 pipeline (Grounding DINO text-prompted box detection -> SAM 2.1 box-to-mask segmentation -> priority-based multi-class fusion -> confidence scoring/QA flagging) and then routes only uncertain images to a human-in-the-loop SAM 3 manual refinement GUI. The production schema is the 3-class "absorber" schema (0=background, 1=fence_wood [the only stain target], 2=not_target) defined in configs/annotation_schema_binary.yaml; a legacy 24-class schema also exists. Exact model IDs are IDEA-Research/grounding-dino-base for detection, facebook/sam2.1-hiera-large for segmentation (with a sam2-hiera-large fallback), openai/clip-vit-base-patch32 for the OOD scene pre-filter, and Meta's SAM 3 image model for interactive manual cleanup. Two bulk-triage scripts (auto_accept_positives, auto_review_negatives) clear obvious cases so humans only touch the genuinely ambiguous ones, and export_final materializes the auto+manual merged training-ready files. A LoRA fine-tune script for Grounding DINO exists but is an offline experiment, not part of the standard run. Note: the DINOv3 ViT-L/16 production segmentation model is a separate downstream subsystem and is NOT referenced anywhere in annotation/.

## NARRATIVE
## Step 4 — AI-assisted labeling and manual mask refinement

This is the stage that turns a folder of scraped fence photos into pixel-accurate training labels. It is a two-layer system: a fully automatic "Grounded-SAM 2" labeling pipeline that produces a first-pass mask for every image, and a human-in-the-loop refinement layer that only ever touches the images the auto pass is unsure about. Everything lives under `annotation/` and is driven by one of two class-schema YAMLs in `configs/`.

### The class schema — what actually gets labeled

The production schema is `configs/annotation_schema_binary.yaml`, and despite the "_binary" filename it defines three classes (the comment at the top explains the name is kept for backward compatibility). Class 0 is background (undetected pixels), class 1 is `fence_wood` — the only thing the stain visualizer paints, drawn bright red `[255,0,0]` so it pops in QA review — and class 2 is `not_target`, a deliberate "absorber" class. The clever bit is the priority numbers: `not_target` sits at priority 60, above `fence_wood` at priority 50. When Grounding DINO ambiguously matches something both as "cedar fence" and as "wood siding" or "wooden chair", the higher-priority absorber wins the pixel and it does NOT get stained. From the stainer's point of view the output is still binary — `stain_mask = (class_map == 1)` — but the third class gives DINO a graceful "out" for the false positives (stone walls, buildings, furniture, vinyl/metal fences) that a pure-binary scheme would have been forced to mislabel as wood fence. Both real classes use box_threshold 0.25 / text_threshold 0.20, tuned toward recall.

There is also a legacy `configs/annotation_schema.yaml` with 24 classes organized into five functional tiers (fence, distractor, occluder, context), with fine-grained fence materials, occluders like `human_animal` (priority 90 — never misclassify a person), `vegetation_occluder` (80), `construction_maintenance` (76, for stacked fence boards that look almost identical to an installed fence), and so on. The CLI still accepts it via `--schema`, but it is the older approach; the default and production path is the 3-class file (`annotation/cli.py:45-50` literally calls the 24-class one "legacy").

### The automatic pipeline — box to mask

`AnnotationPipeline.annotate_one` (`annotation/pipeline.py`) is the heart of it and runs a clean sequence per image:

1. **Scene pre-filter (CLIP).** Before spending GPU on detection, a zero-shot CLIP classifier (`openai/clip-vit-base-patch32`, `annotation/scene_classifier.py`) checks whether the image is actually an outdoor fence scene or an out-of-distribution one (interior room, document/poster, abstract close-up, product shot). It never skips the image, but an OOD verdict tags it `scene_ood=<kind>`, forces `needs_review=True`, and halves the confidence.

2. **Detection (Grounding DINO).** The detector is `IDEA-Research/grounding-dino-base` — the larger ~680M-param "base" variant for accuracy, loaded through HuggingFace `transformers` (`annotation/grounding_dino.py`). Each class contributes a list of text prompts (the 3-class schema has ~24 wood-fence phrasings for class 1 and a long absorber list for class 2). Prompts are joined with the `" . "` separator DINO expects, and there is careful token-budget management to stay under DINO's hard 256-token text-position-embedding cap (headroom 230). Test-time augmentation is on by default — it detects on the original and a horizontal flip, un-flips the boxes, and merges with cross-pass NMS for a few extra points of recall. If a normal pass finds zero detections, the pipeline retries once with all thresholds scaled to 0.6x (floored at 0.10/0.08) and flags the result as `fallback_detection_used` (confidence penalized to 0.7x).

3. **Filtering + fence-first spatial pass.** Detections go through per-class NMS, a per-class max-box cap (50 in the 3-class schema), and then a "fence-first" spatial filter: where a strong fence (score >= 0.30) is detected, occluder-tier boxes that mostly sit inside it (overlap >= 0.5) are suppressed before they ever reach SAM, so vegetation/foreground objects can't steal fence pixels. Humans and absorbers are deliberately exempt from this suppression.

4. **Segmentation (SAM 2.1).** Surviving boxes are fed to `facebook/sam2.1-hiera-large` (`annotation/sam2.py`). SAM is asked for three candidate masks per box (`multimask_output=true`) and the highest-predicted-IoU one is kept — this is what naturally preserves the gaps between fence slats. Each mask is then snapped to true image edges with an opencv-contrib guided filter (radius 4, eps 1e-4), with a morphology open+close fallback if the contrib module is missing. There's a robust 2.1->2 fallback: if the SAM 2.1 checkpoint isn't installed it silently downgrades to `sam2-hiera-large`.

5. **Fusion.** `annotation/fusion.py` collapses all the per-instance masks into one class map by painting low-priority masks first and overlaying higher-priority ones, with two protective rules. Strong/moderate fences are protected from occluder over-detection (constants FENCE_PROTECT_CONF 0.20, STRONG_FENCE_PROTECT_CONF 0.25, OCCLUDER_OVERRIDE_CONF 0.30), and an absorber may only overwrite a fence pixel if it beats the fence's confidence by at least ABSORBER_OVERRIDE_MARGIN (0.07). That single margin is what stops a real cedar fence being "absorbed" by a "wood siding" match while still routing genuine walls/buildings away from staining.

6. **Save + score.** Three artifacts are written per image: `masks/<id>.png` (8-bit, pixel value = class id, so it looks near-black), `masks_preview/<id>.png` (white only where the stain target is), and an optional colorized `viz/<id>.png`. Then `annotation/qa.py` computes an area-weighted confidence and a set of flags; any flag at all sets `needs_review=True` and the image is appended to `qa_queue.jsonl`. The 3-class QA thresholds (min_overall_confidence 0.25, min_fence_wood_confidence_for_positives 0.22, 10% random sample) are noticeably looser than the legacy schema's (0.55/0.40), because the two schemas produce different score distributions.

The batch driver (`annotate_manifest`) adds a background image prefetcher, append-only resumable `results.jsonl`, OOM auto-retry, and a `--retry-missing` mode that reprocesses any image whose results row exists but whose mask file is absent on disk.

### Triage — clearing the easy cases so humans focus

Rather than make a person look at all ~33K images, two bulk scripts pre-decide the obvious ones. `auto_accept_positives.py` stamps high-confidence positives as reviewed WITHOUT changing their masks — but only if the image is manifest class `pos`, its subcategory is on a curated wood-fence whitelist (style_cedar, style_wood, damaged_construction, lighting, general_positive), its coverage is in [0.05, 0.90], confidence >= 0.30, and detections in [1, 80]. The whitelist is the real safeguard: confidence alone can't tell a wood fence from a confidently-detected chain-link fence, so ambiguous subcats are never auto-accepted. `auto_review_negatives.py` is the mirror image — it wipes masks to all-zero and stamps as negative for three sources: manifest `neg`, auto zero-coverage, and a false-positive subcategory list (default style_nonwood plus occlusion/scene_context). Both scripts append the same row shape that the manual GUI writes, prune the QA queue, and delete stale heatmaps, so the state is indistinguishable from a human having pressed the key on each image. Whatever survives triage is, by construction, the genuinely ambiguous set — and that's what the manual tool sees first.

### Manual refinement — SAM 3, only where it matters

`annotation/manual_refine_sam3.py` (2319 lines) is the polished review GUI. It loads Meta's SAM 3 image model with the interactive predictor enabled (`build_sam3_image_model(enable_inst_interactivity=True)` + `Sam3Processor`), running bf16 autocast on CUDA. Left/right clicks add/remove regions with cumulative semantics (each click runs SAM independently and is union'd/subtracted, fixing a SAM 2 bug from the older golden-set tool), `X`+drag gives a box prompt, `C` cycles SAM's three candidates, and `B` toggles a manual brush. Crucially, manual refinement is binary — class 2 absorber pixels are dropped to background and the human just decides fence vs. not.

It targets only flagged work through its ordering options: `--order qa-first` surfaces the qa_queue / `needs_review` images first, `--order coverage` puts likely-wrong low-coverage images first, `--only-unreviewed` hides finished images, and resume auto-jumps to the first unreviewed image. On `SPACE` it runs an edge-refinement cascade (DenseCRF with bilateral sxy=80/srgb=13, then guided filter, then morphology, each stage rejected if it shrinks the mask too much) before saving; the `A` key accepts the mask as-is with no refinement. Every save appends a row to `manual_review.jsonl` (the authoritative override log), overwrites the mask/preview/viz, prunes the QA queue, deletes the stale heatmap, and periodically backs up the log. `results.jsonl` and the manifest are treated as immutable.

### Finalization and the offline LoRA experiment

`annotation/export_final.py` materializes the merged training-ready view: it reads immutable `results.jsonl`, applies the latest `manual_review.jsonl` entry per image (last-write-wins), and writes `results_final.jsonl` (overridden rows get confidence 1.0, `needs_review=False`, a `manual_review` flag, recomputed pixel counts) plus `manifest_final.jsonl` (with pos/neg class flips and `class_source` provenance). `annotation/finetune_dino_lora.py` is a separate, optional experiment that LoRA-adapts Grounding DINO (r=16, alpha=32, ~5M trainable params, bf16, batch 1 / grad-accum 8, lr 5e-5, 15 epochs) on training-set masks-converted-to-boxes, picking the best adapter by golden-set recall. It exists to make DINO better at "wood fence" prompts but is not wired into the standard run.

### What is current vs. leftover

The auto pipeline files, both triage scripts, `manual_refine_sam3.py`, `export_final.py`, the schema loader, and `annotation_schema_binary.yaml` are all current. `manual_sam.py` is the older single-image SAM 2 tool (the one with the non-cumulative click bug) and is superseded. `refine_backup.py` is a 1231-line older snapshot of the SAM 3 GUI — a backup. `sam3_test_pipeline.py` is a standalone benchmarking/experiment that runs SAM 3 text-prompted auto-annotation into `dataset/sam3_test/` and isn't the production path. And to be explicit: nothing in `annotation/` references the DINOv3 ViT-L/16 production segmentation model — the only "hiera-large" strings here are SAM 2's checkpoint names; DINOv3 belongs to a separate downstream subsystem.
